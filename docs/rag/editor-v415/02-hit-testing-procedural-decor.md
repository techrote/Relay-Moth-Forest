# Hit testing, procedural decor and exact reproductions

## Reported Tin Stream failure

User attempted to remove a bush on the bridge/island area. The bush remained, while a nearby rivet objective visual disappeared.

This is reproducible from current code/data.

### Root cause A: right-click is not decor-only

Right-click calls `eraseAt(p,true)`, but `true` only excludes path/water items. Objectives remain eligible.

Because objectives are pushed after explicit decor/grass and have enlarged bounding boxes, they can win the hit.

### Root cause B: the bush is procedural

The offending bush is generated by `StaticPainter.drawDecor()`, not represented in `editor_decor`.

Current generated-decor algorithm:

```text
decorCount = floor(78 * room.foliageDensity)
seed = hash32(room.index + 91, i, 731)
choose tile
skip wall / water / border / decor_exclusions
standing decor when seed % 17 == 0
otherwise plant when seed % 3 == 0 or near path
```

The editor does not enumerate those generated plants as individual selectable items.

When no explicit item is hit, right-click can only suppress the whole tile through `decor_exclusions`.

## Exact Tin Stream generated bridge plants

At current main baseline, deterministic generated decor places these plants on bridge/island geometry:

```text
tile [19,9]  foliage_v401_grove_r2c0
tile [21,10] foliage_mix_02
tile [19,11] foliage_mix_14
```

Tin Stream objective placements include:

```text
rivet_c [19,8]
rivet_d [20,10]
```

The plant at `[21,10]` is next to `rivet_d`; the expanded rivet editor bbox overlaps it.

The immediate manual suppression for that bush is:

```json
"decor_exclusions": [[21,10]]
```

## Other generated-decor evidence

The same generic decorator can place plants adjacent to objectives in multiple rooms.

Current baseline also generates a plant **on the Dawn Heart objective tile**:

```text
room dawn_tree
objective dawn_core [24,9]
generated foliage_v391_21 on [24,9]
```

Therefore the v4.15 fix should not be a Tin Stream-only exclusion patch.

## Target architectural fix

Factor generic procedural decoration placement into a shared deterministic enumeration function/service consumed by both:

- `StaticPainter`
- `WysiwygEditor`

The editor should receive stable descriptors for each generated item, including:

- stable ID derived from room + generator index/type;
- sprite;
- tile;
- logical x/y;
- category/type;
- source = procedural;
- bbox or sufficient geometry to construct it.

The editor must not maintain a second hand-copied version of the generation algorithm.

## Reserved-surface rule

Generic automatic decoration should skip at least:

- bridge cells;
- bridge island;
- exact objective tiles;
- transition/gate footprints if those are otherwise eligible;
- explicitly reserved structural surfaces introduced later.

This restriction applies to **automatic/generated clutter**.

Explicit user-authored decor should remain capable of overriding those areas deliberately.

## Target deletion behavior

When right-clicking generated decor:

1. hit-test the generated item as DECOR;
2. add its tile/ID to the appropriate exclusion representation;
3. leave gameplay objects untouched;
4. rebuild only the visual subsystem required;
5. allow later restoration through suppressed-content UI.

The exact Tin Stream reproduction must become a regression test.
