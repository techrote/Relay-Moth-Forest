# Persistent identities and logical group semantics

Persistent IDs are gameplay/save compatibility, not cosmetic labels.

Current story state persists sets of:

- completed objective IDs;
- collected moth IDs;
- recruited robot IDs;
- current room and shown story state.

## Decorative/recruitable robot move hazard

`copySelectionData()` preserves the robot object including `id`.

But `pasteDataItem()` for robot currently does:

```js
const d=clone(c.data);
d.tile=[tx,ty];
delete d.id;
this.replaceByTile(...)
```

This runs for both copy and move.

Therefore moving an existing persistent/recruitable robot can silently remove its persistent ID.

Target rule:

- **move preserves ID**;
- copy must have explicit semantics.

Recommended v4.15 copy behavior for persistent robots:
- either generate a new globally unique recruitable ID through a deliberate code path;
- or convert copied instance to decorative and clearly notify the user.

Do not silently strip identity without feedback.

## Relay moth IDs

`uniqueId(prefix, arr)` currently checks only the array passed from the current room.

Editor moth creation uses:

```text
editor_moth_1
editor_moth_2
...
```

A new room can independently create `editor_moth_1`.

Moth collection state is global across the campaign, so duplicate IDs can cause one pickup to suppress another.

Target rule: new persistent IDs must be unique across all rooms.

## Wildlife group representation defect

Current `collectItems()` does this for each `creature_group`:

1. find every live creature whose runtime ID starts with the group ID;
2. push one editor item **for every live creature**;
3. every pushed item uses the same underlying group object and same editor ID.

This means a box selection can contain multiple refs to one logical group.

Consequences include duplicate copy/move/delete processing and ambiguous selection counts.

Target model:
- one logical wildlife group = one editor item;
- bbox can be the union of currently visible members plus the spawn handle;
- properties belong to the group: id, kind, count, spawn, seed.

## Mini robots

Mini robot groups are already closer to one-ref-per-group.

Move must preserve group ID.
Copy must assign a new globally unique group ID.

## Objective IDs

Objective IDs come from story authority and must not be regenerated by map editing.

Moving an objective changes only its map placement.

## ID validation

v4.15 semantic validation should detect at least:

- duplicate moth IDs across all rooms;
- duplicate persistent robot IDs across all rooms where IDs are present;
- duplicate wildlife group IDs;
- duplicate mini-robot group IDs;
- map objective IDs that do not exist in story;
- story objective IDs that lack map placement.

IDs generated by copy/paste should be deterministic-enough to understand and unique without scanning only the current room.
